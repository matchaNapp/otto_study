# otto_study
OTTO推荐系统学习手记：从理论到工程实践

## 为什么开始这个学习笔记？

在尝试真正进入推荐系统工程实践之前，我一直认为自己已经掌握了一些算法基础。

我学习过协同过滤、多任务学习、I2I 召回、双塔模型等推荐系统相关理论，也尝试根据自己的理解实现一些基础算法。

但是，当我真正开始寻找项目进行实践时，才发现：

> **理解一个算法和真正把一个算法应用到真实数据中，中间还有很大的距离。**

在这个过程中，我遇到了很多困难：

- 学习过协同过滤、机器学习等理论算法，但面对真实数据时，不知道应该如何进行工程实现；
- 了解算法思想，却不熟悉实际项目中常用的数据处理方式和 Python 工具库的使用；
- 面对大规模数据时，不知道如何进行有效的数据处理和降维，有限的硬件设备甚至无法支撑最基础的实验；
- 一个看似简单的修改，可能需要运行几个小时才能知道是否有效，甚至直接出现内存不足的问题。

这些问题让我意识到：

仅仅学习算法公式和理论知识，并不能让我真正具备完成一个工程项目的能力。

---

## 从理论学习到第一次实践

在正式开始拆解开源项目之前，我首先学习了一些推荐系统常见算法和多目标学习策略，并尝试根据自己的理解实现部分基础算法。

其中包括：

- ItemCF、Surprise 等协同过滤方法；
- Swing；
- BGE；
- Airbnb I2I 召回等。

我曾将自己未进行工程优化的 ItemCF 和 Surprise 实现提交到 Kaggle OTTO 官方比赛，得到：

| 方法 | Private Score | Public Score |
|---|---:|---:|
| ItemCF | 0.41779 | 0.41805 |
| Surprise | 0.29312 | 0.29311 |

这次实践让我第一次真正意识到：

> **理论上理解一个算法，并不意味着能够顺利地将它运行在真实的大规模数据上。**

例如，BGE 和 Airbnb 等算法由于计算复杂度较高，我当时并不知道应该如何进行降维或工程处理，两份实现都没有成功运行到得到最终结果。

这也成为我开始拆解开源项目的直接原因。

详细的理论学习和第一次算法实践记录见：

## 从算法学习到工程实践

为了解决这些问题，我开始尝试自己动手实现一些学习过的基础算法。

但是在实践过程中，我又发现了另一个问题：

很多时候，我并不是不会写代码，而是不知道**为什么应该这样设计**。

我掌握了算法最终呈现出来的公式，却缺少：

- 面对真实数据时的处理思路；
- 针对工程限制进行调整的方法；
- 在不同问题场景下选择合适方案的经验。

因此，我开始寻找一种新的学习方式：

> **耐心拆解一个优秀的比赛开源项目。**

相比于直接阅读理论资料，优秀的开源项目提供了一个更加接近真实工程的视角：

- 面对同一个数据集，经验丰富的开发者会如何处理？
- 为什么他们选择这样的数据结构和处理流程？
- 一个函数或者优化技巧，究竟解决了什么实际问题？
- 当基础算法无法满足需求时，他们如何进行改进？

## 我的学习方式与这份笔记的定位

本笔记主要通过拆解优秀开源项目，记录自己的理解过程。

我不会直接复制或重新发布他人的代码，而是：

1. 阅读开源项目的实现；
2. 理解其中的数据处理、算法设计和工程优化思路；
3. 总结代码背后的原因，而不仅仅记录代码本身；
4. 尝试将学习到的方法应用到自己的基础实现中；
5. 通过实验验证不同方法的效果。

相比于简单展示代码，我更希望记录：

> 针对一个具体工程问题，我们为什么使用某个方法，以及这个方法解决了什么问题。

这份笔记不是完整的推荐系统教程，也不是对开源项目的重新实现。它更像是一份学习过程记录——从一个掌握了一些基础算法知识、但缺少项目经验的学习者视角出发，记录自己如何理解真实工程代码，以及如何逐渐建立工程思维。

我希望通过这种方式：

- 帮助刚开始接触项目实践的人减少“不知道从哪里开始”的焦虑；
- 帮助只学习过理论知识的人理解算法如何进入真实应用；
- 让阅读者不仅知道某个库或者函数怎么使用，更理解它为什么会出现在真实项目中。

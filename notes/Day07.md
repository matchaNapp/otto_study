## Day07：学习汇总与工程总结

### 1. 比赛文件提交

在汇总学到的内容之前，首先尝试将所学到的开源方法结合之前消融实验的结果，并进行适当简化，用于 Kaggle 官网比赛提交。

#### 1.1 PE 单线召回结果

基于该召回方法仅使用 test 数据，在 valid 集合中已经取得较好的效果，进入前四，因此首先直接将其 Top-20 召回结果提交到 Kaggle。

最终取得 **0.48848** 的线上成绩，优于此前使用全量数据构建共现转移矩阵得到的 **0.41779**。

#### 1.2 排序模型

由于原始模型的三路召回及完整特征工程在当前电脑配置下难以运行，因此进一步从召回候选池、特征以及排序模型输入三个维度进行简化。

具体来说，去除相似度特征的计算，候选池仅使用 PE 得到的 Top-50 结果；排序模型的 valid 标签则从开源协议中的三百多万 session 中抽取八万条进行小样本读取；特征方面仅保留 user 和 item 两类基础特征。

最终得到 **0.4796** 的线上成绩。

#### 1.3 结果总结

两次线上提交结果表明，在当前计算资源和数据规模下，**PE 单线召回已经能够取得较好的线上效果，且优于此前基于共现转移矩阵的方案**。进一步加入简化后的排序模型后，成绩下降至 0.4796，说明当前简化配置下，额外的排序环节并没有带来增益。

结合前面的 valid 集实验来看，当前项目中表现较稳定的仍然是基于行为顺序和时间衰减的统计召回方法。相比于在有限计算资源下强行复现完整的多路召回和排序流程，选择结构更简单、内存占用更低的 PE 作为主线方案更加实际。


### 2. 工程处理总结

#### 2.1 数据量降维

A. 按时间截断，仅保留最近一周的数据。

B. 限制 session 长度，仅保留最后 30 个操作。


#### 2.2 存储结构降维

A. 稀疏矩阵存储：使用 `sparse.coo_matrix()` 构建共现矩阵，并以 pkl 格式存储。

B. 使用树结构（Annoy）存储 w2v 向量结果。

C. 使用 npz 格式存储序列数据。


#### 2.3 计算效率降维

A. 减少特征使用。例如作者的 itemcf 仅基于物品计算相似度，不区分操作类型，预测时只看最后一个物品的相似度，从特征维度减少计算量。没必要一个模型用到全部数据，可以尝试多模型针对不同维度分别建模，最后集成。

B. `heapq` 部分排序代替全排序，使用堆结构保留 TopK，时间复杂度 O(k log n) 远低于全排序 O(n log n)。

C. 向量化运算替代 Python 循环，使用 `np.array()` + `@nb.jit` 加速。

D. 分批读取 + 多核并行，相比一次读取所有数据单线运算效率大幅提升。


#### 2.4 时间维度降维

A. 限制共现窗口为 8h。

B. 仅保留最近一周数据，训练时过滤掉前 7 天数据，因为过早的数据可能对模型训练带来负面影响。


### 3. 推荐系统方法与实验模块

#### 3.1 候选召回算法

**A. 基于物品的协同过滤（ItemCF）**

使用 `implicit` 库的 BM25Recommender 构建基于物品共现关系的相似度模型。输入为 session 与 aid 的交互矩阵，不区分具体操作类型；预测时以测试 session 最后一个 aid 为中心，召回 Top-50 相似物品。

特点：通过物品之间的共现关系进行相似物品召回，代码实现较为简洁，但小样本下共现信息有限，Recall@20 ≈ 0.188。


**B. 基于历史用户行为序列召回（Past Event）**

核心思路是对 session 内的历史行为按照时间顺序进行加权，距离当前行为越近的物品具有更高权重，同时结合不同行为类型的重要性进行调整。

权重随行为位置采用指数形式衰减：

$$
\text{weight} = 2^{\text{linspace}(s, 1, \text{len})} - 1
$$

其中 clicks 的衰减起点为 0.1，carts 和 orders 的衰减起点为 0.5；行为权重分别设置为 clicks=1、carts=10、orders=3。

特点：能够直接利用 session 内的行为序列和时间顺序建模当前会话的即时兴趣，计算量较小，在三路召回方法中表现最好，Recall@20 ≈ 0.395。


**C. 基于共现矩阵召回（Co-visit）**

通过统计同一 session 内物品之间的共现关系构建候选集合，仅保留时间间隔小于 8 小时的物品对。针对不同预测目标采用不同的共现权重方式，其中 clicks 主要依据时间关系赋权，carts 和 orders 主要依据行为类型赋权。

对于时间权重模式，权重范围为 [1.0, 4.0]；对于操作权重模式，clicks、carts 和 orders 的权重分别为 1.0、6.0 和 3.0，同时对反向共现关系统一施加 0.3 的方向衰减。

特点：能够利用不同 session 之间的物品共现关系扩展候选池，但小样本下物品对覆盖不足，共现矩阵较为稀疏，因此 Recall@20 ≈ 0.013。


#### 3.2 向量表示方法（Embedding-based）

**D. Word2Vec（开源实现）**

使用 `gensim.models.Word2Vec` 对 session 内的 aid 序列进行 Skip-Gram 训练，使经常出现在相似上下文中的物品获得相近的向量表示。模型使用 64 维 embedding，窗口大小为 3，并采用负采样进行训练。

训练完成后，将归一化后的物品向量存入 AnnoyIndex，并构建近似最近邻检索索引。

特点：主要用于学习物品之间的语义相似关系，在当前系统中生成 w2v_sim 相似度特征并输入排序模型，而不直接作为独立召回结果。


**E. BGE（自写 Skip-Gram）**

使用 PyTorch 实现 Skip-Gram 模型，并将序列中的基本单位由单个 aid 扩展为 aid 与操作类型的组合，从而同时建模物品信息和用户行为类型。

模型采用经典的正负样本与负采样损失进行训练：

$$
L = -\log \sigma(v_c^T v_p) - \sum \log \sigma(-v_c^T v_n)
$$

其中正样本由窗口内的上下文行为构成，负样本随机采样。窗口大小为 3，每个正样本对应 5 个负样本，embedding 维度为 64，训练 3 个 epoch。

特点：相比仅使用 aid 的 Word2Vec，能够引入行为类型信息，但当前版本主要作为备用 embedding 特征，v2 版本中已不参与最终预测。


**F. Airbnb（自写 Skip-Gram + 全局上下文）**

在 BGE 的 Skip-Gram 训练基础上进一步加入 session 级全局上下文信号，将每个 session 中最后一次 order 行为作为额外监督信息，使物品表示不仅考虑局部窗口关系，也能够感知 session 的最终购买目标。

总损失由局部 Skip-Gram 损失和全局上下文损失组成：

$$
L = L_{\text{skipgram}} + \lambda \cdot L_{\text{global}}
$$

其中 λ=0.1，用于平衡两部分监督信号。模型使用 64 维 embedding，训练 2 个 epoch，batch size 为 512。

特点：相比 BGE 增加了 session 级的长期行为信息，但当前版本同样主要作为备用 embedding 特征，v2 版本中已不参与最终预测。


#### 3.3 序列神经网络实验（未并入主线）

**G. Deep Recall（多段时间池化 + MLP）**

将历史行为划分为短期、中期和高价值行为三部分，分别对应近 7 天行为、近 21 天行为以及加购或买单行为。每段序列先进行 masked mean pooling，再将多个行为表示拼接，通过两层 MLP 得到当前 session 的表示向量。

模型采用基于正负样本的余弦相似度对比训练，正样本选取 24 小时窗口内的目标物品，并按照 5:1 的比例采样负样本。短期和中期序列最大长度分别设置为 50 和 100，embedding 维度为 64。

特点：能够同时建模不同时间尺度下的行为信息，但作为候选池重排方法时 Recall@20 ≈ 0.227，低于 ItemCF_v3 的 0.392，因此未并入主线系统。


**H. SASRec（单层自注意力）**

使用单层 Transformer 自注意力结构建模 session 内的序列依赖关系，通过因果掩码保证预测当前位置时不能访问未来行为，并结合位置编码区分不同行为在序列中的顺序。

模型采用基于正负样本的点积对比损失，与 Deep Recall 使用的余弦相似度不同。序列最大长度为 50，注意力头数为 2，embedding 维度为 64；训练时关闭注意力权重输出以减少额外计算。

特点：能够显式建模序列中不同位置之间的依赖关系，但小样本训练下效果未超过传统方法，作为候选池重排时 Recall@20 ≈ 0.208，低于 ItemCF_v3 的 0.392。


#### 3.4 排序模型

**I. LightGBM（LambdaRank）**

将多路召回方法生成的候选 aid 合并，并为每个 session-item 对构建排序特征，最终使用 LambdaRank 学习候选物品之间的相对排序。

特征主要包括 session 级统计特征、item 级时间相关特征、session-item 交叉特征以及不同方法产生的相似度特征。其中 session-item 交叉特征进一步考虑历史行为的时间衰减关系，相似度特征主要包括 Word2Vec、Co-visit 和 ItemCF 的 last、mean 和 max 相似度。

最终评价指标按照不同行为目标进行加权：

$$
\text{overall} = 0.1 \cdot R_{\text{clicks}} + 0.3 \cdot R_{\text{carts}} + 0.6 \cdot R_{\text{orders}}
$$

特点：能够融合多路召回结果和多种统计特征，对候选集合进行进一步区分和排序。在参考开源方案的候选构建和排序思路后，我重新实现了特征提取和排序流程，使用基础统计特征的版本在当前小样本测试集上达到 Recall@20 ≈ 0.402。


### 4. 总结：从开源学习到工程实践

#### 4.1 项目目标与学习路径

这个项目的起点不是“实现一个最优的推荐系统”，而是通过拆解一个完整的开源竞赛方案，理解推荐系统从数据处理、候选召回到特征构建和排序的完整工程流程，并尝试将其中的核心思路迁移到自己的代码中。

在这个过程中，我首先建立了一个固定的小样本验证环境。在硬件资源有限、无法直接进行全量训练的条件下，通过固定的数据切分和统一的 Recall@20 评估方式，保证不同算法之间的实验结果具有可比性。

随后，我按照推荐系统的完整链路逐步拆解开源项目，包括数据预处理、多路召回、向量建模、特征工程和排序模型。在理解各模块作用的基础上，我没有完全照搬原始代码，而是尝试用自己的方式重新实现部分算法，并对早期手写的 ItemCF、BGE、Airbnb 等模型进行调整，使其更适应当前的 session-based recommendation 场景。

整个过程中，我保留了学习笔记、代码迭代过程和实验结果。对我来说，这个项目的重点不只是最终的指标，而是建立一套能够不断测试、比较和修改不同推荐算法的实验框架。


#### 4.2 核心认识

**统计方法仍然可以作为很强的基线。** 在当前的小样本环境下，Past Event 这类基于时间衰减和行为权重的统计方法表现优于多个向量模型和序列神经网络。这说明，在数据规模有限的情况下，充分利用时间、顺序和行为类型等显式信号，往往比直接增加模型复杂度更有效。

**多路召回的价值更多来自候选覆盖。** 即使 Co-visit 单路召回的效果较低，将不同召回路径合并后，排序模型仍然能够获得更好的整体效果。这说明多路召回并不要求每一路都具有很高的独立精度，更重要的是不同方法之间能够形成互补，减少目标物品没有进入候选池的情况。

**开源方案的最佳结果与自己的实验结果需要区分理解。** 在参考的开源方案中，三路召回候选池结合基础统计特征是该方案内部的较优配置，Recall@20 ≈ 0.398。而在我自己的实现中，在参考其候选构建、特征提取和排序思路的基础上重新设计代码流程，使用基础统计特征进行排序后获得了 Recall@20 ≈ 0.402。这两个结果对应不同的代码实现和实验过程，因此更适合作为理解和验证开源工程思路的参考，而不应简单地进行绝对比较。

**特征工程和候选质量对排序效果同样重要。** 在自己的实验中，基础统计特征已经能够提供较强的排序信息，而加入部分深度向量特征后不一定能够带来提升。这也让我认识到，模型复杂度本身并不直接决定最终效果，特征是否稳定、候选池是否覆盖目标以及不同模块之间是否真正形成互补，往往更加重要。


#### 4.3 值得保留的工程习惯

回顾整个学习过程，以下几种思路对后续项目具有较高的复用价值：

1. **先建立固定的小样本验证环境。** 在资源有限时，优先保证实验可复现、可比较，再逐步扩大数据规模。一个稳定的实验环境比频繁更换数据和评价方式更容易发现真正有效的改动。

2. **采用多路召回加排序的两阶段架构。** 召回阶段重点解决候选覆盖问题，排序阶段重点区分候选之间的相关性。不同模块可以独立调整，也便于后续增加新的召回路径或特征。

3. **根据数据规模选择合适的数据结构。** 对共现关系等大规模数据使用稀疏矩阵进行存储，并通过 TopK 截断控制中间结果规模，可以在有限内存下完成原本难以直接运行的计算。

4. **优先利用简单且明确的行为信号。** 时间、行为顺序和操作类型通常是推荐数据中最直接的信息。在尝试更复杂的模型之前，先充分利用这些基础信号，往往能够获得更稳定的结果。



#### 4.4 写在最后

这个项目让我最深的感受是，阅读开源代码的价值并不是找到某一行“最优解法”，而是理解一套完整的决策过程——在不同的数据规模、计算资源和效果要求下，作者为什么选择这样的数据处理方式、召回策略和模型结构。

真正有价值的部分，是在理解这些选择之后，尝试自己重新实现，并通过实验观察哪些思路能够迁移，哪些方法在新的实现和数据环境下并不一定有效。

因此，这个项目最终形成的不只是一个推荐系统的实现，更是一套从阅读开源代码、拆解工程结构，到独立实现和实验验证的学习过程。这些笔记和代码也会继续保留在 GitHub 上，作为后续学习推荐系统和进行工程实践的基础。

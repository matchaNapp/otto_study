## 2. 特征排序输入的结构

阅读 `importance.csv` 文件并查看读取数据的格式后，发现里面是处理之后的 4 列数据。

第一列是作者提取出来的 97 个特征名称，后面 3 列分别是这些特征对应 clicks、carts 和 orders 三种操作的重要性分数。

从命名来看，包含 `i_`、`ui_`、`u_`、`candidate_rank` 等前缀的特征应该来自不同的特征提取文件，后续可以从对应的 Python 文件进一步理解各类特征的构建方式。

## 3. 基于数据的特征提取

### 3.1 `user_fe.py`

文件通过均值、中位数等简单数学统计方式提取多个候选特征。

`u_session` 开头的特征表示每个 session 对应一个统计值；`u_aid` 开头的特征同理，以不同 aid 为单位进行统计，长度对应 aid 去重后的数量。

但这里的数据仅针对训练集进行离线处理，没有合并 test 数据集的历史数据，同时也没有使用时间信息。

### 3.2 `item_fe.py`

这里 `i_` 开头的特征表示每个 item 对应一个统计特征。

这个数据集更多是从时间角度对不同 aid 进行打分。特别地，代码标记了 train 数据集最后一周和 test 数据集开始的时间，并以这些时间点为定位构建多个特征。

同时，train 数据集过滤掉了最开始一周的数据。

### 3.3 `user_item_fe.py`

这个文件下的操作全部仅针对于测试集数据。

这里的特征开始尝试将一个特征结合多类原始数据，同时加入不同操作的 `type`，统计每一个物品在不同 session 中的出现顺序以及操作顺序。

特别地，此处针对各 session 下不同 aid 的行为序列设计了经典的指数时间衰减模型相关特征。

**时间衰减权重公式**

$$
\text{ui log score} =
2^{\left(
0.1 +
\frac{1 - 0.1}{\text{session length} - 1}
\times
(\text{session length} - \text{ui action reverse} - 1)
\right)} - 1
$$


| 符号                  | 含义                                    |
| :------------------ | :------------------------------------ |
| `ui_log_score`      | 该行为的时间衰减权重，越新的行为权重越高                  |
| `session_length`    | 当前 session 的总行为数                      |
| `ui_action_reverse` | 该行为在 session 内按时间倒序的序号，0 表示最新，值越大表示越老 |
| `0.1`               | 最小权重系数，确保最老的行为也有一定权重                  |
| `1.0`               | 最大权重系数的基准值                            |
| `2`                 | 指数底数，控制衰减曲线的陡峭程度                      |
| `-1`                | 最终偏移量，使最小权重接近 `0.1` 而非 `1`            |

**权重分配逻辑**

* 最新行为 `ui_action_reverse = 0` 时，指数部分接近 `1`，权重接近 $2^1 - 1 = 1.0$。
* 最老行为 `ui_action_reverse = session_length - 1` 时，指数部分接近 `0.1`，权重接近 $2^{0.1} - 1 \approx 0.07$。

**设计意图**

让 session 内越靠近末尾、也就是越新的行为获得更高权重，越老的行为权重越低，从而实现时间衰减效果。

## 4. 基于相似度的特征提取

### 4.1 `w2v_sim.py`：Word2Vec 相似度特征

具体操作在之前详细展开的 `w2v_sim.py` 文件里面。

W2V 模型相似度特征提取步骤为：

1. 提取调用 W2V 后得到的 aid 向量。
2. 对每个候选 aid，相对该 session 整段历史 aid 分别计算相似度。
3. 分别提取 `last`、`mean` 和 `max` 三类统计值。

其中，`last` 表示候选与历史中最后一个 aid 的相似度。

候选对象来自 BM25 模型的召回结果。

特别地，上述操作都是以 session 为聚合基准，因此最终会得到每一个 session 下不同 aid 对应的三个维度相似度特征。

### 4.2 `covisit_sim.py`：共现矩阵相似度特征

该过程和 4.1 类似，只不过计算相似度的来源变为 `covisit_matrix.py` 中共现矩阵直接提取的权重。

这里使用的候选对象同样来自 ItemCF 中 BM25 模型召回得到的候选 aid。

### 4.3 `itemcf_sim.py`：I2I 查表相似度特征

这里候选池不再仅仅使用 ItemCF 中 BM25 模型召回得到的结果，而是分别使用 ItemCF、Past Event 和共现矩阵三路召回结果作为候选池。

相似度来自 BM25 模型输出字典的查找。和之前以 session 为单位的处理方式相同，对于每一个 session 内不同 aid 提取 `last`、`max` 和 `mean` 三个特征，并集成到一个列表中作为排序特征。

不同候选池根据命名后缀进行区分。

### 4.4 相似度特征提取汇总

总的来说，开源项目构建的三类基于相似度的特征具有共同模式：

> **均在已有候选池的基础上，相对 session 历史行为计算相似度，并提取 `last`、`mean` 和 `max` 三种统计特征。**

差异主要在于：

| 维度    | 差异                                                                         |
| :---- | :------------------------------------------------------------------------- |
| 相似度来源 | W2V 向量 / Co-visit 权重 / I2I pkl 查表                                          |
| 候选范围  | `w2v_sim`、`covisit_sim` 仅使用 `bm4`；`itemcf_sim` 使用 `co` / `pe` / `bm` 三路候选池 |

## 5. 最终排序的小样本实现

参照前面的特征提取文件，全部按照开源代码实现，仅将数据集修改为自己训练使用的小样本集合。

对于提取出来的特征，参照 `ranker.py` 文件，直接带入 LambdaRank 进行排序，并最终计算 Recall@20 得分。

具体来说，排序的输入数据为 train 中除去最后一周的数据加上 test 的历史数据。其中，train 中最后一周的数据被划分为 valid 数据集，用于训练排序模型。

### 5.1 基准结果

| 方法             | Overall      | clicks   | carts    | orders   |
| :------------- | :----------- | :------- | :------- | :------- |
| `past_event_1` | 0.394910     | 0.340696 | 0.202800 | 0.500000 |
| `item_cf_1`    | 0.188468     | 0.201138 | 0.104092 | 0.228545 |
| `covisit_1`    | 0.012916     | 0.030120 | 0.014358 | 0.009328 |
| `ranker_1`     | **0.397031** | 0.381271 | 0.202128 | 0.497110 |

在多特征提取下，最终排序结果比原先任何一个召回单独预测效果都要好，比召回中效果最突出的历史用户行为序列模型高了约 0.002。

### 5.2 消融实验

开源工作的整体思路为：

> 三路召回结果合并作为候选池 → 使用简单数学公式提取基础特征 → 结合 W2V、共现矩阵和 ItemCF 提取相似度特征 → 将所有特征输入排序模型。

基于最终输入特征来看，实际上只有少部分来源于相似度特征，大部分依靠的仍是基础数学统计特征。

此外，三路召回结果中仅有 `past_event` 表现较好，其它结果较差，因此设计如下消融实验。

#### 5.2.1 去除相似特征

去除相似度特征后，仅使用基础数学公式提取出来的特征投入模型进行排序。

#### 5.2.2 候选池仅使用 `past_event`

候选池仅使用 `past_event` 作为依据，不再使用三路召回结果。

| 实验                               | Overall      | clicks   | carts    | orders   |
| :------------------------------- | :----------- | :------- | :------- | :------- |
| `ranker_stat_1` 去除相似特征           | **0.398037** | 0.377926 | 0.195035 | 0.502890 |
| `ranker_pe_1` 仅 `past_event` 候选池 | 0.380817     | 0.357860 | 0.202128 | 0.473988 |

**结论**

三路召回作为候选池，加上基础数学公式提取的统计特征，在当前小样本集合中取得了最高分。

## 6. 实践：候选池与深度模型接入

### 6.1 候选池的添加

发现在特征提取部分，开源代码都是基于 BM25 模型得到的召回结果作为候选池，然后再计算相似度，最终用于排序模型。

基于之前的学习和训练，发现我的所有召回代码中 [`itemCF_v2`](../restart/itemCF_v2.py) 的单模型召回结果最好。

因此，下面的 [`itemCF_v2`](../restart/itemCF_v2.py) 仅作为候选池，用于我其它已有的 [`deep_recall`](../restart/my_deep_recall.py)、[`sasrec`](../restart/my_sasrec.py)、[`airbnb_v2`](../restart/airbnb_v2.py)、[`BGE_v2`](../restart/BGE_v2.py) 模型提取出的向量。

#### 6.1.1 数据预处理

首先对 [`itemCF_v2`](../restart/itemCF_v2.py) 文件进行修改，使输出结果变为每一个 `type` 保留 100 个预测 aid 候选，并另存为候选表：

```text
(session, type, aid, rank)
```

修改后代码为 [`itemCF_v3`](../restart/itemCF_v3.py)。

这里仅改动预测结果的截断数量，不改动邻居矩阵中的 Top-20。

特别地，对于 [`BGE_v2`](../restart/BGE_v2.py) 和 [`airbnb_v2`](../restart/airbnb_v2.py) 文件的向量读取，需要首先将 pair 维映射回 aid。

#### 6.1.2 具体计算过程

首先提取需要预测的 session 下对应 `type` 候选池中的 `aid_i` 向量。

然后遍历该 session 的所有历史 `aid_j` 向量，分别计算 `aid_i` 与 `aid_j` 之间的余弦相似度。

最终，候选池中每个 `aid_i` 的得分为：

> 与 session 历史 aid 的余弦相似度求和后取均值。

根据候选池中所有 aid 的最终得分重新排序，再截断为 Top-20，并计算 Recall@20。

#### 6.1.3 结果统计

以 ItemCF_v3 的召回结果构建候选池后，对比多种 embedding 的池内余弦重排。

结果均显著低于 ItemCF_v3 原生排序：

> **0.39 → 0.15–0.23**

这表明在当前小样本环境下，基于操作类型和时间构建的指数衰减策略仍然占主导作用，序列模型和 Skip-Gram 向量可能更适合作为可选特征，而不是独立精排器。

| 方法                 | Overall      | clicks   | carts    | orders   |
| :----------------- | :----------- | :------- | :------- | :------- |
| `itemCF_v3` 基线     | **0.391581** | 0.358434 | 0.198851 | 0.493470 |
| `sasrec_on_itemcf` | 0.208222     | 0.260040 | 0.105528 | 0.250933 |
| `deep_on_itemcf`   | 0.226696     | 0.278782 | 0.121680 | 0.270522 |
| `bge_on_itemcf`    | 0.155998     | 0.229920 | 0.092606 | 0.175373 |
| `airbnb_on_itemcf` | 0.151218     | 0.229920 | 0.089734 | 0.168843 |

### 6.2 特征提取相关消融实验尝试

为了尝试验证“序列模型和 Skip-Gram 向量可能更适合作为可选特征，而不是独立精排器”的猜想，下面首先将 `itemCF_v3` 本身和之前在候选池基础上表现较好的 `deep_on_itemcf` 作为排序模型的输入进行尝试。

具体来说，对于两者均输入 `last`、`max` 和 `mean` 三类信息，具体提取方式与开源项目相同。

最终结果如下：

| 方法                   | Overall      | clicks   | carts    | orders   |
| :------------------- | :----------- | :------- | :------- | :------- |
| `itemCF_v3`          | **0.391581** | 0.358434 | 0.198851 | 0.493470 |
| `itemcf_only_ranker` | 0.333384     | 0.326087 | 0.170213 | 0.416185 |
| `deep_only_ranker`   | 0.346935     | 0.362876 | 0.168440 | 0.433526 |
| `item_deep_ranker`   | 0.346458     | 0.379599 | 0.184397 | 0.421965 |

可以看到，加入 ItemCF 提取的相似度特征后结果下降。

在此基础上加入 Deep 的相似度特征后，结果虽然有所上升，但仍然没有原本不进行特征排序时的效果好。

因此，在分数提升的过程中，占主导作用的很有可能是基础数据本身提取出来的统计特征。

接下来尝试不再使用任何额外相似度特征，仅学习开源项目 `fe` 对应文件中的基础特征提取方式，将这些特征合并成一个特征表格后输入排序模型。

最终结果如下：

| 方法                                | Overall      | clicks   | carts    | orders   |
| :-------------------------------- | :----------- | :------- | :------- | :------- |
| `data_ranker(based on itemCF_v3)` | **0.402205** | 0.379599 | 0.196809 | 0.508671 |

发现在 ItemCF_v2 召回的候选池基础上，仅学习开源方法从基础数据中通过均值、中位数等简单数学方式得到的特征并带入排序模型，在 valid 小样本数据集上取得了最好的结果。

同时，因为我的 ItemCF_v2 召回虽然效果较好，并且和 `past_event` 在行为建模思路上具有一定相似性，但前者额外使用了共现矩阵存储，因此内存更容易出现不足。

考虑到希望在 Kaggle 竞赛中选择一个在内存占用方面更有优势的方案，开源提供的 `past_event` 思路可能更适合。

基于这个想法，下面增加了将 ItemCF_v2 候选池替换为 `past_event` 候选池的版本进行测试。

最终所有结果存储在 [`results.txt`](../restart/results.txt) 文件中。

在所有 valid 集测试中，Recall@20 排名前 4 的方法如下：

| 方法                                | Overall      | clicks   | carts    | orders   |
| :-------------------------------- | :----------- | :------- | :------- | :------- |
| `data_ranker(based on itemCF_v3)` | **0.402205** | 0.379599 | 0.196809 | 0.508671 |
| `pe_airbnb_ranker`                | 0.397991     | 0.356187 | 0.202128 | 0.502890 |
| `past_only_ranker`                | 0.396395     | 0.356187 | 0.196809 | 0.502890 |
| `past_event` 基线                   | 0.394910     | 0.340696 | 0.202800 | 0.500000 |

其中，ItemCF_v3 使用用户时间衰减序列构建转移共现矩阵，空间复杂度较高；Airbnb 同样使用了共现转移矩阵。

## 7. 今天的核心认识

1. **开源特征工程的核心价值在基础统计特征**

   `user_fe`、`item_fe`、`user_item_fe` 通过均值、中位数、时间衰减等简单数学方式提取的特征，比深度向量相似度特征对排序的贡献更大。

2. **多路召回合并仍有增益**

   即使 Co-visit 和 ItemCF 单路 Recall 不高，三路合并后排序仍然优于仅用 `past_event` 做候选池，说明多路召回的价值在于提升候选覆盖，而不是单路精度。

3. **深度向量在小样本上还不足以独立精排**

   用 [`deep`](../restart/my_deep_recall.py)、[`sasrec`](../restart/my_sasrec.py)、`BGE`、`airbnb` 在候选池上做余弦重排，分数显著低于原版召回，说明在小样本上基于操作和时间的指数衰减策略仍然主导。

   深度向量更适合作为候选特征列接入排序模型，而不是独立召回或精排器。

4. **开源工作学习闭环**

   从 `past_event` → `covisit` → `w2v` → `BGE/airbnb` → [`my_deep_recall`](../restart/my_deep_recall.py) → [`my_sasrec`](../restart/my_sasrec.py) → `ranker`，今天完成了从召回到排序的完整闭环学习，开源项目的核心工程思路已经全部走通。
